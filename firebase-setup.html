DayShape.
ONE-TIME OWNER SETUP

Your family.
Connected everywhere.

Set up Firebase once. Then every iPhone, iPad, and computer uses the same family space. No Dropbox app keys on each device.

1. Register DayShape as a web app

Open your project in the Firebase console. In Project settings → General → Your apps, add a Web app (the </> icon) named DayShape. Firebase Hosting and Google Analytics are not needed for this update.

Copy the public firebaseConfig object. It contains apiKey, authDomain, projectId, and appId. Send that object to your coding agent to put in firebase-config.js and publish. These web configuration values identify your project; access is protected by Authentication and Firestore rules. Never send a service-account JSON file, private key, or account password.

2. Turn on parent sign-in

Under Build → Authentication → Get started → Sign-in method, enable Email/Password. Email-link sign-in is not used.

Under Authentication → Settings → Authorized domains, add niwde787.github.io (hostname only). Add localhost and 127.0.0.1 only if you need local development. In Authentication’s email templates, set the app name to DayShape for verification and password reset messages.

3. Create the cloud database

Under Build → Firestore Database, create the default database, choose Standard edition, and select a region near your family. Start in Production mode. This app does not use Realtime Database, Cloud Storage, or Cloud Functions.

The no-cost Spark plan is a sensible starting point for a small family. Watch the Usage tab; if you hit its quotas, cloud operations pause until quota is available. Local queued edits remain on the device.

4. Publish the family access rules

Open Firestore Database → Rules. Replace the default rules with the complete file below and click Publish. These rules require verified accounts, family membership, and a matching email invitation. Do not use open “allow everyone” rules or Test mode.

Download firestore.rules

Alternatively, from the app’s source folder, run npx firebase login, then npx firebase deploy --only firestore:rules --project YOUR_PROJECT_ID. This deploys rules only; the website stays on GitHub Pages.

5. Open your family space

  1. After the configured app is published, open DayShape and select Account & sync (or Sign in / Cloud sync on the welcome screen).
  2. Create your parent account and verify your email. Return to DayShape and tap I’ve verified my email.
  3. Create one family space. On the device containing your existing profiles, choose Import this device’s profiles. Your local copy is kept and existing cloud IDs are not overwritten.
  4. To add your spouse, enter their exact email under Add another parent. Copy and share the family code with them. Invitations expire after 7 days. DayShape does not send invitation emails.
  5. Your spouse creates and verifies their own account, then joins with that code. On your other devices, sign in to the same parent account to reopen your existing family automatically.

Child profiles do not need email addresses. Both parent accounts can view and edit every family profile.

6. Check it on two devices

Add a test activity on one device. Wait for Saved to cloud, then check the second device. Turn one device offline, make another test change, reopen it online, and verify the change arrives on the other device. Same-record conflicts use the last cloud write; separate activities sync independently.

Sync runs while DayShape is open; iOS may suspend it in the background. Sign-out waits for pending edits and removes this session’s local family copy. Use trusted devices and export a backup before clearing browser storage. Removing a parent’s membership prevents future access, but cannot erase data already downloaded to their devices.
